# Blender scene pipeline

The 3D hospital is generated by a script, so it is reproducible and reviewable.

| File | Purpose |
|---|---|
| `build_hospital.py` | Builds the scene from `shared/hospital_layout.json` and exports `frontend/public/models/hospital.glb` plus `hospital.mapping.json` |
| `render_preview.py` | Renders a Workbench preview of the built `.blend` (used for `docs/images/blender-preview.png`) |
| `out/` | Generated `.blend` (git-ignored; rebuild any time) |

```bash
blender --background --factory-startup --python blender/build_hospital.py -- \
  --layout shared/hospital_layout.json \
  --out frontend/public/models/hospital.glb \
  --blend blender/out/hospital.blend
```

Verified with Blender 5.2.2 LTS in background mode. Rules the script enforces:

* Each modeled asset is one node named `AST_<ASSET-ID>` with the custom property `asset_id`,
  exported as glTF `extras`. The frontend resolves selections through `extras.asset_id`
  and checks every backend asset against the GLB at load time.
* Equipment templates are shared mesh data, so instances reuse geometry.
* Walls are merged into one mesh per material; there are no textures, lights or cameras.
* `backend/tests/test_twin_mapping.py` parses the GLB and fails if the mapping drifts from the
  backend inventory.

The Blender MCP server was not used for generation: the session's MCP connection needed a
running Blender with its add-on, and its CLI mode could not locate the Blender binary. The
headless script gives the same result and anyone can re-run it.
